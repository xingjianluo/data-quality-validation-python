# data-quality-validation

本地数据质量契约的校验与监控服务：统一契约模型、可区分的错误分类、
并发/重复执行下确定一致的判定，以及完整性/唯一性/新鲜度指标的可回溯历史。

## 快速开始

```bash
uv sync                       # 或使用现有环境
uvicorn main:app --reload     # http://127.0.0.1:8000/docs
python3 -m pytest -q -s       # 运行测试并查看用例判定日志
```

## 能力一览

- **契约定义与校验**：类型、必填、可空、取值边界、枚举、长度、正则、唯一性
  归一为统一 `FieldSpec`；契约非法、约束冲突、字段缺失一律带 `category+reason`
  拒绝，不静默跳过。注册为**严格白名单**：任何不认识的契约级/字段级配置项
  （含约束名拼错）都按非法契约拒绝并指出具体位置。
- **执行与异常归一化**：数据不满足约束（`data_violation` /
  `data_missing_field`）与依赖自身故障（`dependency_failure`）分为不同类别，
  依赖原始异常不直接透出。
- **幂等并发**：以 `(contract, batch_id)` 为幂等键，并发/重复提交返回同一首次
  结论，指标只累计一次、漂移只判定一次。
- **指标历史**：完整性、唯一性、新鲜度快照在批次首次判定时冻结；阈值/SLA 变更
  不回写历史；可经 trace 回溯到契约、批次与触发原因。全可选字段契约合法，
  完整性按 1.0 计并写明取值依据。
- **基线漂移**：当前批次可与最近已判定批次（默认）或显式指定的历史批次对比，
  按每指标可配的容忍幅度判定完整性/唯一性/新鲜度是否退步；基线不存在或未判定
  时明确拒绝而非硬凑。基线、幅度与结论在批次首次判定时固化，之后新批次、
  调整容忍幅度或重注册契约新版本都不改写老批次。

## 模块结构

```
app/quality/
  errors.py     # 错误大类与归一化异常
  contracts.py  # 契约统一模型、归一化、严格白名单与非法/冲突拒绝
  engine.py     # 校验引擎、依赖异常归一化、唯一性
  metrics.py    # 完整性/唯一性/新鲜度的冻结快照
  drift.py      # 基线漂移判定（基线对比、容忍幅度、结论模型）
  storage.py    # 线程安全、幂等的本地留存（结果/指标/漂移结论）
  service.py    # 编排：注册、幂等提交、指标与漂移判定、回溯
  api.py        # FastAPI 路由与错误码映射
tests/          # 严格契约、漂移固化、并发重复、全可选契约等测试
docs/data-quality-contract.md  # 语义、错误分类、指标与漂移判定规则
```

完整语义与错误码表见 [`docs/data-quality-contract.md`](docs/data-quality-contract.md)。
